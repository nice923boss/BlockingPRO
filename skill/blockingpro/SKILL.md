# BlockingPRO 預演專案產生

工具資料夾（下稱 `ROOT`）：`<ROOT>`。這裡若還是尖括號佔位字，代表 SKILL 沒有經過安裝，請到 BlockingPRO 資料夾執行 `python tools/install_skill.py`。

| 用途 | 位置 |
|---|---|
| 專案格式逐欄說明（座標、路徑、角色、物品、攝影機、剪接） | `reference/format.md` |
| 所有代號：動作、體型、動物、內建物品尺寸、燈光預設、焦距 | `reference/catalog.md`（由 runtime 產生） |
| 自訂物品格式 | `reference/assets.md`（由 runtime 產生） |
| 檢查專案並渲染每一鏡、俯視圖、MP4 | `ROOT/tools/check_scene.py` |
| 改了 runtime 後重新產生 catalog.md / assets.md | `ROOT/tools/gen_reference.py` |
| 比對修改前後的專案，列出改了哪些欄位 | `ROOT/tools/project_diff.py` |
| 檢查長故事各段前後是否連戲、列出一段結束時的狀態 | `ROOT/tools/check_continuity.py` |
| 讀劇本，每一場產生一個骨架專案（角色、字幕、說話動作、節拍標記） | `ROOT/tools/script_import.py` |
| 參考圖與渲染圖比對（混合、邊緣疊圖、像素格線） | `ROOT/tools/compare_ref.py` |
| 範例專案 | `ROOT/examples/street-meet.blockingpro.json`、`cafe-talk.blockingpro.json`、`dog-walk.blockingpro.json` |

寫 JSON 前先讀 `reference/format.md`，用到的動作、物品、體型代號以 `reference/catalog.md` 為準，不憑記憶。

## 流程

1. **讀故事**：抓出角色（人、動物）、場景、道具、關鍵動作、情緒轉折。使用者只給一句話時，自己補成 3 到 6 個節拍的短故事，交付時說明補了什麼。使用者給的是劇本（有場次標題、「角色：台詞」）時，先照「劇本匯入」產生骨架再往下做。
2. **拆鏡頭**：寫出鏡頭表（鏡號、起訖秒數、攝影機、景別與運鏡、畫面內容）。規則：
   - Seedance 2.0 參考影片單段 15 秒內、1280x720（直式 720x1280）。故事太長就拆成多段，每段一個專案，寫法見「長故事拆成多段」。使用者指定其他模型（Seedance 2.5、Kling、Veo、Runway Aleph）時，`settings.target` 填對應代號，長度與解析度照 catalog.md 的「目標模型」表；Veo 3.1 不收參考影片，改交首尾格 PNG。
   - 每鏡 1.5 到 5 秒；景別要有變化（全景交代空間，中景看動作，特寫看情緒）。
   - 先決定走位，再決定機位：同一場對話的機位都放在兩人連線的同一側（180 度線），剪接時左右才不會跳。
3. **算走位**：在 XZ 平面上擺好每個人、物品的位置與時間，確認速度（走路 1.2 到 1.5 公尺/秒）、人與人間距 0.6 公尺以上、人不穿過家具（尺寸看 catalog.md）。
4. **寫專案資料夾**，沒指定位置就放 `ROOT/projects/<英文代號>/`：
   - `project.blockingpro.json`：專案檔（UTF-8）。拆成多段時改成 `part1.blockingpro.json`、`part2.blockingpro.json`……
   - `assets.blockingpro-assets.json`：選填，只有用到自訂物品時才寫（同一批物品也要放進專案檔的 `assets`，見「自訂物品」）。
   - `storyboard.md`：分鏡表，格式見下。
5. **檢查並渲染**：
   ```bash
   python "<ROOT>/tools/check_scene.py" "<ROOT>/projects/<英文代號>/project.blockingpro.json" --shots --overview 0,<中段秒數>
   ```
   輸出在 `project_check/`。最後一行是 `sheet.png`（每鏡取中間一格，標秒數、機位、鏡頭說明）。前面會列出每一鏡量到的景別，以及「提醒：穿模」「提醒：越軸」。
6. **看圖修正**：Read `sheet.png` 和 `overview_*.png`，逐鏡確認：
   - 主體在畫面裡、沒被牆或物品擋住、沒有黑畫面或空景。
   - 景別和鏡頭表一致（特寫真的是特寫）。先看輸出的景別清單，不一致的鏡頭改機位、焦距，或改鏡頭表。
   - 「提醒：穿模」逐條修：改路徑繞開、加路徑點、挪家具或錯開時間。
   - 「提醒：越軸」逐條看：對話與相遇的機位改回同一側；刻意的反拍（例如從物品後方拍）可以保留，在 storyboard.md 的「說明」寫明是故意的。
   - 俯視圖上的路徑不穿過家具和牆，攝影機視線方向對。
   - 有疑問的時間點用 `--times 2.5,6.1` 輸出單格細看。運鏡的起點、中段、終點也用 `--times` 各取一格，確認運動方向對（Read 看不了影片，`--mp4` 只用來交給使用者）。
   錯誤（exit code 1）必修；警告逐條判斷。修完回到步驟 5，直到 0 錯誤且每一鏡畫面正確。
7. **交付**（見文末）。

## 劇本匯入

使用者貼上或給一份劇本（有場次標題、「角色：台詞」、動作描述），要做成預演時，先用工具產生每一場的骨架，再補走位和鏡頭：

1. **存檔**：貼上的文字存成 `projects/<英文代號>/script.txt`（UTF-8）；給的是檔案就直接用。工具只讀純文字（UTF-8 或 Big5），docx、PDF 要先轉成文字。
2. **產生骨架並讀大綱**：
   ```bash
   python "<ROOT>/tools/script_import.py" "<ROOT>/projects/<英文代號>/script.txt" --out "<ROOT>/projects/<英文代號>"
   ```
   每一場寫成 `scene<N>/project.blockingpro.json`（超過 15 秒的場次拆成 `part1`、`part2`……）。大綱列出每場的地點、燈光、總秒數和每個節拍的時間；先只看大綱不寫檔就拿掉 `--out`。工具認得的寫法：場次「第1場　黃昏　外　公車站」、「人物：小雯（女）、阿哲（男）」、「阿哲：台詞」或「阿哲（喘氣）：台詞」、動作行（開頭的 △ 會去掉；動作行裡有冒號時一定要加 △），以及 Fountain 格式。名字單獨一行、台詞寫在下一行的寫法認不出來，先改成「名字：台詞」。
3. **骨架有什麼**：角色（每場的說話者和「人物：」行的名字，各場同一個 id 和顏色，一字排開面向鏡頭；體型看人物行的註記，女、男、童、老，沒寫就是 man）、每句台詞一個 `talk` 片段和一條字幕（`subtitles`，帶說話者）、每行動作和括號說明一個時間標記（`settings.markers`）、一台全景 camA。時間是估計值：台詞每秒 4 個中文字，動作行 2 秒，節拍間隔 0.3 秒。
4. **補完每一場**：照流程步驟 1 到 6 做，骨架當作節拍表：
   - 改 `preset`、`color`（骨架的體型可能不對），擺位置、補路徑和動作；時間標記就是該演的節拍，動作照標記的時間放。
   - 只在動作行出現的角色（沒說話、也不在人物行）骨架裡沒有，自己加。
   - 補場景物品、燈光（骨架依場次標題的日夜內外猜）、攝影機和剪接。骨架只有 camA。
   - 走位需要更多時間時，把後面的字幕、`talk` 片段和時間標記一起往後移，`duration` 跟著加長，三者時間要對得上。
   - 同一場拆成多段時，照「長故事拆成多段」的連戲規則寫，用 check_continuity 檢查。
5. **storyboard.md**：一份涵蓋所有場次，每場一張鏡頭表；「說明」寫哪些秒數是為了走位改過的、劇本有但白模做不出來的（下雨、表情）。
6. **交付**：每場各附一張 sheet.png。各場是獨立的專案資料夾（`scene1/`、`scene2/`），在編輯器裡一次開一場。範例：`ROOT/projects/umbrella-script/`。

## 長故事拆成多段

故事超過目標模型的單段上限（Seedance 2.0 為 15 秒，其他看 catalog.md 的「目標模型」表）時，拆成多段，每段一個專案，放在同一個資料夾，前後連戲：

1. **分段**：先寫完整個故事的鏡頭表，再在節拍之間切段，每段不超過上限。切點選在動作停住的時候（坐著、站定、對看），不要切在走路或交物品的中途。
2. **檔案**：`projects/<英文代號>/part1.blockingpro.json`、`part2.blockingpro.json`……；`name` 寫成「公園還書（第 1 段，共 2 段）」，編輯器開啟資料夾時會列出各段讓使用者選。storyboard.md 只寫一份，每段一張鏡頭表，鏡號接續。
3. **連戲規則**（每一段照前一段結束時寫）：
   - 角色、物品沿用同樣的 id、名字、體型、顏色、大小；場景物品位置不變；`settings`（`duration` 除外）和 `lights` 照抄；自訂物品放進每一段的 `assets`。
   - 下一段 t = 0 的位置、yaw 等於前一段結束時的位置、朝向。
   - 前一段結束時還拿著的物品，下一段第一個 attach 片段不寫 `from`，`actor`、`joint`、`upright` 和前一段相同。
   - 前一段結束時還在做的動作（坐著、躺著、講電話），下一段在 t = 0 放同一個片段並寫 `"blend": 0`；不寫會從站姿淡入 0.3 秒，接起來姿勢會跳。
   - 寫下一段前，先列出前一段結束時每個角色、物品的狀態，照著寫下一段的 t = 0：
     ```bash
     python "<ROOT>/tools/check_continuity.py" "<ROOT>/projects/<英文代號>/part1.blockingpro.json"
     ```
4. **段與段之間當成剪接**：下一段開頭換一台攝影機、換景別，接起來才不像跳接。要接同一個鏡頭時，把前一段最後一台攝影機複製到下一段（位置、aim、lens 都相同）。
5. **檢查**：每段照流程步驟 5、6 跑 check_scene，再檢查各段前後是否連戲：
   ```bash
   python "<ROOT>/tools/check_continuity.py" "<ROOT>/projects/<英文代號>"
   ```
   逐對列出「第 n 段結束 → 第 n+1 段開始」的不連戲項目（位置差、朝向差、姿勢不同、拿的人或握法不同、顏色或體型不同、設定不同），exit code 0 才算連戲。攝影機和燈不比對，姿勢只比頭部相對腳的位置，手的姿勢要看截圖。
6. **交付**：每段各附一張 sheet.png，說明分成幾段、各段長度、切在哪個節拍。範例：`ROOT/projects/park-book/`。

## 分鏡方案比較

使用者要「幾種分鏡方案」「給我選拍法」「比較不同運鏡」時，同一場戲做 2 到 3 個方案讓使用者挑，挑完才寫分鏡表：

1. **走位只寫一次**：照流程步驟 1 到 3 寫好角色、物品、動作，所有方案共用；方案之間只換 `cameras`、`cuts`、`name`。某個方案非改走位不可時（例如一鏡到底要角色停在攝影機前），在 variants.md 寫明改了什麼。
2. **方案要真的不同**：每個方案用一種鏡頭語言，例如：

   | 方案 | 做法 | 適合 |
   |---|---|---|
   | 古典 | 全景交代空間，接中景、過肩正反打，固定機位 | 對話、資訊多的戲 |
   | 運動 | 跟拍、推軌、環繞，鏡數少 | 走路、追逐、節奏快的戲 |
   | 一鏡到底 | 一台攝影機連續運動，不剪接 | 開場、情緒連續的戲 |
   | 情緒特寫 | 特寫、過肩、低角度多 | 衝突、告白、反應 |

3. **檔案**：同一個資料夾放 `variant-a.blockingpro.json`、`variant-b.blockingpro.json`、`variant-c.blockingpro.json`；`name` 寫成「街頭相遇（方案 A：古典正反打）」，編輯器開啟資料夾時會列出各方案。
4. **檢查**：每個方案照流程步驟 5、6 跑 check_scene，修到 0 錯誤且每一鏡畫面正確。只有 1、2 鏡的方案（一鏡到底）另外用 `--times` 取起點、中段、終點各一格。再確認方案之間只差攝影機、剪接和名字：
   ```bash
   python "<ROOT>/tools/project_diff.py" "<專案資料夾>/variant-a.blockingpro.json" "<專案資料夾>/variant-b.blockingpro.json"
   ```
5. **給使用者挑**：寫 `variants.md`（一張表：方案、檔案、做法、鏡數、check_scene 量到的景別順序、優點、缺點；優缺點只寫看得到的事實，不推測生成效果），用 SendUserFile 傳每個方案的 sheet.png（caption 寫方案名，一鏡到底的方案加傳 `--times` 的格），請使用者選一個，或指定混搭（例如「C 的開場接 A 的過肩」）。這一步先不寫 storyboard.md。
6. **選定後**：選中的檔案改名為 `project.blockingpro.json`，`name` 拿掉方案字樣；沒選的改名加 `.bak`（例如 `variant-b.blockingpro.json.bak`，編輯器不會讀到），交付時告訴使用者確認後可以刪除。混搭時從最接近的方案照「修改既有專案」的步驟改。接著重跑 check_scene、寫 storyboard.md，照「交付」完成。範例：`ROOT/projects/street-meet-options/`。

## 修改既有專案

使用者給既有的專案資料夾或專案檔，要求只改某幾鏡、某個角色時，照下面做，不整份重寫：

1. **備份**：把 `project.blockingpro.json` 複製成同資料夾的 `project.blockingpro.json.bak`（副檔名不是 .json，編輯器開啟資料夾時不會讀到）。
2. **對照鏡號**：先跑一次 check_scene（流程步驟 5 的命令），景別清單會列出「鏡 N：起訖秒數，攝影機」，用它把使用者說的「第 3 鏡」對到 `cuts` 的剪接點和攝影機 id；使用者說角色名字時，對到 `actors` 的 id。
3. **只改指定的部分**：
   - 這台攝影機也被別的鏡頭用到時，改 path、aim、lens 會連帶改到別鏡：只在這一鏡的時間範圍內加關鍵影格，或複製一台新 id 的攝影機給這一鏡，再改這個剪接點的 `camera`。
   - 改角色的路徑、動作會影響所有拍到他的鏡頭，交付時列出受影響的鏡號。
   - id、`version`、看不懂的欄位、沒提到的角色與物品原樣保留，不重排、不補預設值。
   - 手寫排版的檔案（一行寫好幾個值）用 Edit 只替換要改的值，不重新排版。編輯器儲存的檔案（2 格縮排、一行一個值）可以用短 Python 腳本 `json.load` 改完再 `json.dumps(obj, indent=2, ensure_ascii=False)` 寫回，排版和編輯器相同，文字差異只出現在改到的地方。
4. **確認差異**：
   ```bash
   python "<ROOT>/tools/project_diff.py" "<專案資料夾>/project.blockingpro.json.bak" "<專案資料夾>/project.blockingpro.json"
   ```
   逐行列出哪個角色、物品、攝影機、剪接點的哪個欄位從什麼改成什麼（角色等依 id 對應，剪接點依秒數對應，改了秒數的剪接點會列成一個刪除加一個新增）。出現沒打算改的項目就改回來。
5. **重新檢查**：照流程步驟 5、6 跑 `--shots`，和改之前的景別清單比對；改到的鏡頭和受影響的鏡頭都重看截圖。
6. **更新分鏡表**：storyboard.md 只改有變的列（鏡頭表、提示詞），插入或刪除鏡頭時重編後面的鏡號；剪接點的 `note` 跟著改。
7. **交付**：附 project_diff 的輸出、受影響的鏡號、新的 sheet.png，並告訴使用者 .bak 確認後可以刪除。

## 參考圖反推機位

使用者給一張電影劇照、分鏡圖或截圖，說「照這張的機位拍」「反推這個鏡頭」時，估出攝影機位置、對準點和焦距，再用渲染比對修正。這個流程只在 BlockingPRO 自己的渲染圖上驗證過（6 張，見 GAPS G046），真實劇照的鏡頭畸變、演員身高差異沒有測過，交付時要說明。

1. **先擺好主體與背景**：照流程步驟 1 到 3 擺好畫面裡的人和物品；`settings` 的寬高比和參考圖相同。主體放在原點附近最好算。
2. **盲估**（只看圖）：在參考圖上量像素座標（圖寬 W、中心 c），依可用線索選用：
   - 焦距：畫面裡有兩組互相垂直的水平線（地板磚、牆角、桌邊）時，各找消失點 v1、v2，`f² = -(v1 - c)·(v2 - c)`（像素），`lens = f × 36 / 長邊像素`（BlockingPRO 的焦距是 36 mm 全片幅，長邊 36 mm）。
   - 俯仰：水平線（地平線或消失點連線）在畫面中心上方 Δy 像素，`pitch = atan(Δy / f)`，水平線在上方代表往下看。
   - 距離：主體與背景的大小比。知道兩者的深度差時，`d = 深度差 / (s主體 / s背景 - 1)`（s 是同尺寸物件在畫面上的像素大小）；或用人的實際高度：`d ≈ f × 實際高度 / 像素高度`。
   - 方位：正面看臉時，鼻子偏離臉中線的距離除以半個頭寬，約等於 1.0 到 1.2 倍的 sinθ（θ 是攝影機繞到角色側面的角度）。
   - 白模尺寸（成年女性 1.65 公尺，其他體型照身高等比換算）：頭頂 1.65、鼻子 1.53、下巴 1.43。
   - 有全景（廣角）參考時先解它，用它的地面與家具位置當其他鏡頭的尺。
3. **渲染候選機位**：複製專案，只留一台攝影機 `c1`，`aim` 寫 `{"mode": "point", "keys": [{"t": 0, "v": [x, y, z]}]}`（寫成 `target` 會被忽略），剪接只有 `{"t": 0, "camera": "c1"}`，渲染一格：
   ```bash
   python "<ROOT>/tools/check_scene.py" "<候選專案檔>" --times 0.5
   ```
   check_scene 同時只能跑一個（共用伺服器埠），不要平行跑。
4. **比對**：
   ```bash
   python "<ROOT>/tools/compare_ref.py" "<參考圖>" "<候選專案檔旁的 _check 資料夾>/f_0.5s.png"
   ```
   輸出左半是 50% 混合，右半是邊緣疊圖（紅色參考、綠色渲染、黃色重合），都有像素格線。Read 它，量出差距：
   - 主體偏大、背景卻吻合：攝影機太近，焦距太短，往後退並加長焦距（特寫最常見，盲估的焦距常短 25% 到 35%）。
   - 主體和背景一起偏大或偏小：只調焦距。
   - 近景和遠景往相反方向偏：繞主體轉一點方位（近景偏右、遠景偏左時往右繞）。
   - 整體上下偏移：調 aim 的高度。
   - 一次修過頭（所有線索反向偏差差不多大）：取兩次的中點。
5. **每張最多 3 到 4 次渲染**：邊緣大部分重合（誤差在 5 個像素內）就停；修不掉的差距（例如某個背景邊緣始終在畫面外）在交付時寫出來。
6. **寫進專案**：把結果寫成正式攝影機，跑流程步驟 5、6；交付時附 compare_ref 的比對圖，說明估計的位置、焦距和剩下的差距。

## 座標規則（細節見 format.md）

- 公尺、秒、度。Y 朝上，地面 y = 0；俯視時 X 往右、Z 往畫面下方。
- yaw 0 面向 +Z，90 面向 +X，180 面向 -Z，-90 面向 -X；yaw = atan2(dx, dz)。角色自己的左手邊在 yaw 0 時是 +X。
- 關鍵影格的 `e`（緩動）寫在一段的**起點**那一格。第一格之前、最後一格之後都停在原地。
- 走到定點要轉身：最後一格寫 `yaw`。原地站著一直面向某方向：`"facing": "fixed"` 加 `yaw`。
- 攝影機鏡頭高度：平視 1.5 到 1.7，坐姿平視 1.1 到 1.2，低角度 0.3 到 0.6，鳥瞰 8 以上。
- 看臉：`aim` 用角色加 `offset` [0, 身高 × 0.92, 0]（男 1.64、女 1.52、兒童 1.1）；不加 offset 會看胸口和頭之間，適合中景、全景。

## 運鏡配方

下面以主體在原點、這一鏡在 2 到 5 秒為例。**攝影機關鍵影格的時間要落在這台攝影機被剪進來的區間內**，運動才會出現在成片裡；同一台攝影機被剪進來好幾次時，每段都要有對應的關鍵影格。

| 運鏡 | 寫法 |
|---|---|
| 固定 | `"path": {"keys": [{"t": 0, "v": [0, 1.6, 5]}]}`，aim 看角色或固定點 |
| 推軌（推近） | `"path": {"keys": [{"t": 2, "v": [0, 1.6, 6], "e": "inOut"}, {"t": 5, "v": [0, 1.6, 2.8]}]}`，aim 看角色 |
| 拉軌（拉遠） | 推軌反過來，終點可以升高 0.3 到 0.5 交代環境 |
| 橫移 | `"curve": "linear"`，`[{"t": 2, "v": [-3, 1.5, 4], "e": "linear"}, {"t": 5, "v": [3, 1.5, 4]}]`。aim 看角色會一直把人放中間；aim 用 point 跟著平移（`[-3, 1, 0]` 到 `[3, 1, 0]`）則構圖不變、背景滑過 |
| 搖鏡（水平） | path 固定一格；`"aim": {"mode": "point", "keys": [{"t": 2, "v": [-3, 1.2, 0], "e": "inOut"}, {"t": 5, "v": [3, 1.2, 0]}]}` |
| 仰俯（直搖） | path 固定；aim point 的 y 從 0.2 到 3（由下往上），或反過來 |
| 環繞 | 以主體為圓心，半徑 r、高度 h，每 45 到 60 度放一格：`v = [sx + r·sin(θ), h, sz + r·cos(θ)]`（θ 從 +Z 起算），`"curve": "smooth"`、全部 `"e": "linear"`，aim 看角色。180 度環繞 3 秒約 4 到 6 格 |
| 升降（升起） | path y 從 0.6 到 4.5，水平位置不變，aim 看角色 |
| 跟拍（背後） | `"mount": {"actor": "mei", "offset": [0, 1.7, -3.2], "rotate": true}`，aim 看同一角色 |
| 跟拍（側面） | `"mount": {"actor": "mei", "offset": [3.5, 1.4, 0], "rotate": true}`（角色左側；右側用 -3.5） |
| 正面倒退拍 | `"mount": {"actor": "mei", "offset": [0, 1.5, 3], "rotate": true}`，aim 看角色 |
| 手持 | 任何運鏡加 `"shake": 0.6`（0.3 輕微，1 以上緊張、追逐）；`"shakeStyle"` 換晃法：`walk` 邊走邊拍、`breathe` 幾乎靜止的呼吸感、`vehicle` 車上、`impact` 持續劇烈震動（代號見 catalog.md） |
| 變焦 | `"lens": [{"t": 2, "v": 28, "e": "inOut"}, {"t": 5, "v": 85}]`，path 不動 |
| 希區考克變焦 | 一邊拉遠一邊變焦，焦距 ÷ 距離維持不變：距離 2 到 5.8、`lens` 24 到 70，path 和 lens 都用 `"e": "linear"`，aim 看角色 |
| 鳥瞰 | path 在主體正上方 8 到 10 公尺，**水平偏 0.5 以上**（例如 `[0, 9, 0.6]`），避免正上方時畫面方向亂轉 |
| 低角度仰拍 | `[0, 0.35, 2.5]`，aim 看角色（自然往上看），焦距 24 到 28 誇張身形 |
| 過肩 | 攝影機在前景角色背後偏一側肩膀：A 在 `[0, 0, -0.6]` 面向 +Z，拍 B（`[0, 0, 0.6]`）時攝影機放 `[-0.45, 1.55, -1.7]`（A 的右肩後），aim 看 B 加臉部 offset，lens 45 到 50 |
| 正反打 | 兩台過肩機放在兩人連線的同一側（例如都在 -X 側），輪流剪接 |
| 甩鏡 | path 固定 `[0, 1.6, 5]`；aim point 先停在主體，最後 0.35 秒甩到 90 度外：`[{"t": 2, "v": [0, 1.2, 0]}, {"t": 4.65, "v": [0, 1.2, 0], "e": "in"}, {"t": 5, "v": [5, 1.2, 5]}]`，常接下一鏡當轉場 |
| 荷蘭角 | 任何機位加 `"roll": 18`（10 到 25 度，不安、失衡）；roll 也能寫關鍵影格慢慢傾斜 |
| 螺旋上升 | 環繞加升降：每 30 到 35 度放一格，同時 y 從 h 升到 h + 3，270 度約 9 格，aim 看角色 |
| 穿越前景 | 樹、柱子這類物品放在攝影機和主體之間；攝影機在物品後方約 0.9 公尺、高度 1.3 以下，`"curve": "linear"` 橫移 3.2 公尺，aim 看角色，前景物品會從畫面一側掃過 |
| 推軌加變焦 | 推軌推到原距離的 70%，同時 `lens` 從 l 變到 l × 1.6（例如 50 到 80），比單純推軌更有壓迫感 |
| 景深 | 任何攝影機加 `"dof": {"fstop": 2}`（自動對焦在 aim 的位置），背景糊掉、主體清楚；只在導演台主畫面和輸出出現 |
| 遮幅 | `settings.letterbox` 寫 `"2.39"` 或 `"1.85"`，上下加黑邊做電影感構圖。check_scene 的截圖不畫黑邊：16:9 畫面用 2.39 時上下各裁掉約 13%（1.85 約 2%），主體要放在這範圍以內 |

## 動作與道具要點

- 走路、跑步交給 `autoGait`（預設開）：路徑在動腳就會動，速度決定走或跑，加速、減速、轉彎、原地轉身的步伐會自己過渡。不要再額外放 walk 片段。速度變化用路徑關鍵影格的間距與緩動表達即可。
- 情緒寫進步態：角色加 `"gait": { "style": "tired" }`（疲累）、`hurried`（急促）、`relaxed`（悠閒），`amp` 0.5 到 1.5 調動作幅度；路徑速度配合風格，疲累 0.7 到 1、悠閒 0.8 到 1.1、急促 1.6 到 2 公尺/秒。
- 全身動作（sit、sitting、standUp、jump、bow、fall、dance、pickUp 等）放 `actions`；上半身動作（wave、talk、phone、drink、point、clap 等）放 `upper`，可以邊走邊做。catalog.md 的「軌道」欄寫了每個動作該放哪一軌。
- 坐下：人的位置在椅子中心往椅子正面方向約 0.4 公尺、yaw 和椅子相同，`sit`（1.5 秒）接 `sitting`；坐著時路徑不要動。起身用 `standUp`。座高：椅子、長椅 0.45，沙發 0.42（`params.seat`）。
- 辦公桌的螢幕朝 +Z，坐的人在桌子 +Z 側面向 -Z；吧台的客人側是 +Z。
- 拿東西：物品 path 放在桌上或地上，`attach` 的 `from` 設拿起的時間、`blend` 0.3（滑進手裡），搭配 `pickUp` 或伸手動作；放下時設 `to`，並在 path 補一格放下的位置；丟出去加 `throw` 與 `arc`，path 在落地時間放一格。換手、放下再拿起時 attach 寫成多段陣列。可手持的內建物品見 catalog.md。
- 日常動作：開門 `openDoor`、打字 `typing`、看手機 `lookPhone`、搬箱子 `liftBox` / `carry` / `putDown`、抱小孩 `holdChild`（配 `baby` 物品）、騎機車與腳踏車 `ride`（車子 attach 寫 `"joint": "root"`）。站位、附著時間照 format.md「日常動作配方」，不要自己估。
- 握手、擁抱、遞東西：兩個人都放雙人動作（`handshake`、`hug`、`give` 配 `receive`），`params.with` 填對方，距離與換手寫法見 format.md「雙人動作」。
- 上樓梯、台階、斜坡、舞台：路徑 y 維持 0，走過去身體和腳就會踩上表面。舞台正面放台階 `steps`，樓梯頂端接一個縮放過的舞台當平台，位置算法見 format.md「可行走的物品」。
- 動物只有 `actions`，沒有 `upper`；動作依物種不同（catalog.md 的「適用」欄）。
- 白模顏色：每個角色給不同的 `color`，Seedance 和看預演的人才分得出誰是誰。
- 身形：故事寫到高、矮、胖、瘦、大頭時，用角色的 `body`（身高公尺、胖瘦、頭的大小，見 format.md），同體型的兩個人也分得出來。雙人動作（握手、擁抱、遞物）兩人身高差要在 1.8 倍內。
- 需要特定姿勢（指向某處、抱頭、躺姿調整）時用姿勢片段 `pose`，寫法見 format.md 第 4 節。使用者提到「我存過的姿勢」時，讀 `ROOT/library/poses.json`（format.md「姿勢庫」），把同名條目的 `pose` 抄進姿勢片段；`rig` 要和角色相符（人物都是 `human`）。
- 視線：故事寫到看向某人、某處（回頭看、抬頭看招牌、低頭看小孩）時，用角色的 `gaze`（`actor` 或 `point`），頭會跟著移動的對象轉；只轉頭和脖子，左右 75 度內，對象在身後要先讓角色轉身。寫法見 format.md「視線 gaze」。
- 手勢：指向、揮手、拍手等動作和手上拿東西時會自動換手勢；要比讚、握拳、張開手時，在角色或片段寫 `"hands": {"l": "open", "r": "thumbsUp"}`（format.md「手勢 hands」）。

## 自訂物品

內建物品（catalog.md）沒有的道具才做自訂物品，規則見 `reference/assets.md`：

1. 用 box、cylinder、cone、sphere、capsule、torus 組出輪廓，原點在底部中央、正面朝 +Z、單位公尺，零件 60 個以內。

4. 先單獨檢查物品包，看正面、右前、左後三個角度和 1.7 公尺參考人的比例：


## 常見錯誤

| 錯誤寫法 | 正確寫法 |
|---|---|
| 3 秒走 10 公尺 | 速度 = 距離 ÷ 時間。走路 1.2 到 1.5 公尺/秒，跑步 3 到 6；太快會像滑行 |
| `"e"` 寫在一段的終點那格 | 緩動寫在起點那格，控制「這一格到下一格」 |
| 攝影機推軌的關鍵影格在 0 到 2 秒，但這台攝影機 4 秒才剪進來 | 關鍵影格放在剪接區間內 |
| 第一個剪接點 `"t": 1` | 第一個剪接點寫 `"t": 0` |
| `aim` 或 `mount` 的 actor 填物品 id | 只能填角色 id；看物品用 `"mode": "point"` 寫物品位置 |
| sit、jump 放在 `upper` | 全身動作放 `actions`；`upper` 只放上半身動作 |
| 動物寫 `upper` | 動物只有 `actions` |
| 杯子放在桌上卻寫 `"v": [0, 0, 0]` | 放桌面要寫桌面高度：桌子、辦公桌 0.75，吧台 1.05 |
| 上樓梯時路徑 y 寫成階梯高度 | 角色路徑 y 寫 0，走上可行走物品時高度自動算（物品放桌上才要寫 y） |
| 角色路徑直接穿過舞台邊緣（檢查出現「直接跨上」） | 舞台正面放台階 `steps`，路徑從台階中線走上去 |
| 兩個角色同一個位置、或人站在桌子裡 | 人與人至少 0.6 公尺，和家具的距離依 catalog.md 尺寸算（桌子 1.4 x 0.8，中心到邊緣 0.7 / 0.4） |
| 鳥瞰攝影機放在主體正上方 `[0, 9, 0]` | 水平偏 0.5 以上，例如 `[0, 9, 0.6]` |
| `"lens": "35mm"`、`"color": "red"` | `"lens": 35`；顏色只用 `#rrggbb` |
| 自訂物品只放在物品包、專案檔 `assets` 是空的 | 專案檔 `assets` 一定要放；物品包是給素材庫用的副本 |
| 總長 20 秒的單一專案 | Seedance 單段 15 秒內，拆成兩段（見「長故事拆成多段」） |
| 下一段 t = 0 接著坐著，`sitting` 沒寫 `blend` | 延續前一段的片段寫 `"blend": 0`，不然會從站姿淡入 |
| 對話鏡頭攝影機一台在左一台在右 | 機位放在兩人連線的同一側（180 度線） |
| 人走進坐下但椅子方向相反 | 椅子正面朝 +Z（椅背在 -Z），人坐下時的 yaw 要和椅子 yaw 相同 |

## 交付

1. 回報專案資料夾路徑、鏡頭表摘要、補了哪些故事細節，附 `sheet.png` 給使用者看（SendUserFile）。
2. 在 BlockingPRO 開啟：給使用者這行命令（需要 Python）：`python "<ROOT>/tools/serve.py" --project projects/<英文代號>`。BlockingPRO 沒在執行時會啟動並開瀏覽器，已在執行時只開瀏覽器；編輯器直接載入這個資料夾（目前有場景時會先問要不要取代）。使用者要你代為開啟時，用背景方式執行這行命令（伺服器啟動後會一直執行，不要在前景等它結束）。BlockingPRO 已在執行時，也可以只給網址 `http://127.0.0.1:38940/?project=projects/<英文代號>`。資料夾裡有多段專案時，編輯器會列出各段讓使用者選。專案不在 `ROOT` 裡面時，改用工具列「開啟資料夾」或把資料夾拖進視窗。時間軸上會有運鏡關鍵影格和剪接點，導演台顯示剪接後的畫面。
3. 在編輯器裡調整後按「下載 MP4」輸出參考影片、「儲存」下載專案檔。MP4 對話框可選整段、每鏡各一個、依目標模型上限分段（盡量切在剪接點），畫面可勾白模、關節版、深度圖，格式可選 MP4 或 WebM、畫質低到最高。工具列「更多輸出 ▾」有首尾格 PNG、AI 影片提示詞（整段與每鏡）、GIF 預覽、分鏡表 PDF、鏡頭表 CSV。屬性面板（未選取物件時）的「給哪個模型」切換目標模型，「套用建議規格」一鍵改成 1280x720（直式 720x1280）、24 fps。想改運鏡時，3D 視窗「駕駛」攝影機後按「● 錄製運鏡」，邊播放邊用 WASD、QE 和滑鼠飛，停止後寫成關鍵影格；導演台按「● 導播錄製」，播放中按 1 到 9 切換攝影機，可以即時重剪。鏡頭表有「標示景別」與「越軸檢查」。要給沒裝 BlockingPRO 的人看，MP4 對話框選「一個檔案」、只勾一種畫面，再勾「輸出成分享用 HTML」，下載的 `<名稱>_分享.html` 用瀏覽器打開就能播，附鏡頭表和字幕。
4. 說明檢查範圍：看了哪幾鏡的截圖、俯視圖哪些時間點、剩下哪些警告與原因；運鏡的連續動作只用取樣截圖確認，流暢度沒有逐格看過。

## 限制

- `check_scene.py` 需要 Python 的 `playwright` 套件與 Chromium（`pip install playwright` 後 `python -m playwright install chromium`）。函式庫在 `ROOT/vendor/`，裝好之後離線也能檢查；頁面要求本機以外的檔案時會列為渲染錯誤（exit 2）。
- 白模是預演用的示意：人物沒有臉、衣服，手只有 5 種固定手勢，動作是程式產生的基本動作，不能表演細膩的表情與手指動作。
- 檢查工具輸出靜態截圖，Claude 看不到影片的連續動作；動作流暢度、穿模要在編輯器播放確認。
- 內建握法照成年男性的手調整，其他體型只移動握點、沒有逐一調過；手持位置偏差時用 `attach.pos` / `attach.rot` 修正。`upright` 的物品不會隨手腕傾斜（倒水、斜拿雨傘要關掉）；丟出去的物品沒有碰撞，會穿過桶蓋、桌子。
- 穿模提醒只看地面上的位置（人是圓、物品是 1.8 公尺以下零件的底面方框，每 0.1 秒取樣）：手臂、頭、彎腰前傾、跳起來越過物品都不算，坐下時不檢查和家具的重疊。景別只看每鏡中間那一格，不管物品遮擋（坐在桌後的腿也算看得到）；越軸只比左右順序。這些都要再看截圖確認。
- 有 `model` 欄位的自訂物品是使用者在編輯器匯入的 GLB／OBJ 模型，SKILL 不產生也不改寫（見 assets.md）。檢查這種專案時模型檔要放在專案檔旁邊，缺檔會用半透明方塊代替並提醒。
